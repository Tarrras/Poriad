## 1. Блокери

### Б1. Видалення акаунту не працює ні для кого ✔
`supabase/migrations/20260917100100_delete_my_account.sql:13` робить `delete from storage.objects`. На проді на `storage.objects` висить `protect_objects_delete` (BEFORE DELETE FOR EACH STATEMENT → `storage.protect_delete()`), який кидає 42501, якщо не виставлено `storage.allow_delete_query`. Тригер рівня statement спрацьовує навіть на нуль рядків → уся транзакція відкочується разом із `delete from auth.users`. Жоден тест цю функцію не викликає.

Наслідок: вимога Google Play / App Store 5.1.1(v) формально є в UI, фактично не виконується; сторінка `site/delete-account.html` обіцяє те, чого не відбувається.

Фікс: видалення через Edge Function під service role (`storage.from('event-images').remove(...)` + `auth.admin.deleteUser`). Мінімальний — `perform set_config('storage.allow_delete_query','true',true);` перед DELETE (файли в S3 лишаться сиротами). Плюс тест у `supabase/tests`.

### Б2. Користувача, на якого скаржились, неможливо видалити ✔
`reports.event_id` / `reports.subject_user_id` — `ON DELETE SET NULL`, а CHECK `reports_subject` вимагає їх NOT NULL (`20260906195750_safety_age_and_reports.sql:95-104`, підтверджено в проді). Каскад з `auth.users` → 23514 → відкат. Стосується і видалення події організатора, на яку скаржились. Навіть після Б1 це лишиться.

Фікс: послабити CHECK до `subject_type in ('event','user')` або прибрати FK і зберігати uuid як доказ.

### Б3. Android просить точну геолокацію (V8 не діє) ✔
Зібраний маніфест містить `ACCESS_FINE_LOCATION` — його додає `org.maplibre.gl:android-sdk`. Розходиться з Data safety і `store/listing.md` (Coarse). Також `ACCESS_ADSERVICES_ATTRIBUTION` від Firebase при обіцянці «без реклами».

Фікс: в `androidApp/src/main/AndroidManifest.xml` — `<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" tools:node="remove"/>` (і те саме для `ACCESS_ADSERVICES_ATTRIBUTION`).

### Б4. `APNS_SANDBOX` за замовчуванням `true` + видалення токенів на `BadDeviceToken`
`supabase/functions/push/index.ts:191,214`. Якщо секрет на проді не `false`, кожен пуш на TestFlight/App Store-токен повертає `BadDeviceToken`, і токен стирається з `push_tokens`. Значення секрету через MCP не видно — треба перевірити руками.

Фікс: за замовчуванням production; видаляти токен лише на 410 / `Unregistered`. Перевірка: `supabase secrets list --project-ref tzdogzdvctlumsqlqskr` + тестовий пуш на TestFlight.

### Б5. У чаті не можна заблокувати автора (iOS, App Review 1.2)
`iosApp/Poruch/Features/Detail/ChatView.swift:189-197` — лише «Поскаржитись». `blockUser` є тільки для організатора в деталях. Плюс сервер: блокування не виганяє з кімнати (`can_view_members`, `20260906195750:249-252`), а RPC `remove_member` немає. Android — перевірити так само.

Фікс: пункт «Заблокувати автора» в меню повідомлення на обох платформах.

- Ingest: детерміновані id, ідемпотентний upsert, подвійний запобіжник на масове зняття (≤30%), Nominatim 1.1 с + кеш.
- iOS prod-архів справді prod і лінкує release-фреймворк; `ITSAppUsesNonExemptEncryption=false`; перегляд без входу; Sign in with Apple не потрібен.
