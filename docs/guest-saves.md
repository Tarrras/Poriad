# Закладки гостя

Стан на 2026-10-20: реалізовано на обох платформах, не закомічено, у сторах нема. Тести спільного коду й правил —
PASS; руками перевірено гостем на iPhone SE (iOS 18) і Android 16: закладка без входу → системне питання → «1 scheduled»
у журналі → «Мої події» з рядком про вхід; зняття → порожній стан гостя. Перенесення в акаунт перевірено лише тестами:
вхід на dev руками не робили. Відкрите питання 1 вирішено (питати). Лише клієнт, без міграції. Продовжує [бриф утримання](retention-brief-2026-10.md)
і [канал повернення гостя](guest-channel.md).

## Проблема

Шкала «що отримує людина з 0-го по 60-й день», зібрана з коду 20.10, показала: межа проходить не між гостем і
акаунтом, а між тим, у кого є особистий привід повернутись (закладка, «Стежити», «Йду»), і тим, у кого його нема.
Пуш повернення прив'язаний до пристрою, тож акаунт без жодної дії отримує рівно те саме, що гість. На prod таких 9 з 13.

Гість зберегти подію не може: `EventUseCases.toggleSaved` без акаунта віддає `SessionRequired`, картка веде на вхід
(`auth = .save` на iOS, `AuthReason.SAVE` на Android, `auth_wall` з `save`). Звідси три діри:

1. **Нема особистого приводу.** Усе, що гість отримує за два місяці (4 локальні дайджести й 2 пуші повернення), — один
   шаблон «місто, N подій, дві назви». Нагадування напередодні о 18:00 про збережене — єдиний дотик про подію, яку
   людина вибрала сама, — гостю не дістається: `ReminderRules.plan` при `userId == null` повертає порожній список.
2. **Нема моменту спитати дозвіл.** iOS-гість живе на тихому провізорному дозволі: сповіщення лягають у Центр
   сповіщень без банера. Повне питання звучить на 2-му запуску чи після «Стежити» / «Йду», а гість, що відкрив
   застосунок раз, не робить ні того, ні іншого. Android 13+ питає лише після першої закритої картки.
3. **Вхід стоїть перед першою дією.** Закладка — найлегша дія в застосунку, і саме її ми продаємо за реєстрацію.

## Цілі

1. Гість зберігає подію одним тапом, без входу, скрізь, де є «Зберегти»: картка, стрічка головної, мапа, «Купили?».
2. Напередодні о 18:00 приходить те саме нагадування, що й людині з акаунтом («Завтра о 19:00 · адреса»).
3. Перша закладка — момент повного питання про сповіщення: на iOS з тихого дозволу, на Android 13+ — якщо дозволу ще
   нема.
4. Після входу закладки гостя переходять в акаунт без жодної дії людини.
5. «Мої події» гостя показують розріз «Збережені», а не лише заглушку «Увійдіть».

## Не цілі

- **«Стежити» без акаунта.** Пуші про нове шле сервер, і прив'язати їх без акаунта нема до чого. Якщо закладки
  спрацюють, це кандидат на наступний крок через `private.devices`.
- **Пуші про перенесення чи скасування збереженої гостем імпортованої події.** R6 читає `saved_events` і вимкнений
  перемикачем `event_changes`. Гостя захищає оновлення карток при кожному відкритті (нижче).
- **Закладки гостя на кількох пристроях.** Перевстановлення чи новий телефон — і закладки гостя зникають. Саме це
  чесно пояснює, навіщо входити.
- **Вибір при злитті «лишити мої / лишити акаунта».** Просте об'єднання: закладка нічого не коштує, дубль неможливий
  (`primary key (user_id, event_id)`).

## Дизайн

### Дані: лише на телефоні

- Список id у `device_store` під ключем `device:saved`, JSON-масивом. Префікс обов'язковий: при вході
  `IdentitySync.synchronize` → `library.clear()` → `clearPrivateCache` стирає все без `device:` (`clearPrivateDevice`),
  тобто закладки зникли б ще до перенесення.
- У domain поруч із `SavedEvents` — `GuestSavedStore { ids(); write(ids) }`, реалізація `LocalGuestSaves` за зразком
  `LocalDeviceTouch`. Сервер нічого не дізнається, доки людина не ввійде.

### Спільний код

| Де | Що змінюється |
|---|---|
| `EventUseCases.toggleSaved` | Без акаунта: `library.setSaved` і запис у `GuestSavedStore`, без мережі й без `SessionRequired`. З акаунтом — як зараз |
| `UserLibrary.load()` | Зараз без акаунта виходить одразу. Тепер для гостя — `loadGuest()`: `events.cards(ids)` → `library.myEvents` = картки, `savedIds` = їхні id. Тож оновлення приходить там само, де й для акаунта: у `Reloader.resumed()` і на старті — у `PoruchApp.init` зараз стоїть `if (state.value.signedIn) loadMyEvents()`, умову прибрати |
| `loadGuest()` | `event_cards_by_ids` розгортає злиту подію в живу (`private.live_event_id`), тож замість надгробка повертається живий id. Подія, якої більше нема, випадає, минула (`hasEnded`) — теж. На диск записується те, що лишилось. Збій мережі — лишаємо що є; нагадування стоять за останнім знімком |
| `ReminderRules.plan` | Прибрати `userId == null → emptyList()`. Гостю — лише гілка збережених: «за годину» потребує акаунта (`concerns`). `MAX_SCHEDULED` спільна |
| `MyEventsRules.board` | Гість — лише розріз «Збережені». Без явної гілки `mine = organizerId == userId` при `null` зібрав би в «Організую» всі імпортовані (`organizerId == null`) |
| `LibraryState` | `savesMade` — лічильник, як `followsMade`: платформа бачить першу закладку й питає про сповіщення |

### Перенесення в акаунт

У `UserLibrary.load()`, поруч з `adoptInterests`, за тим самим правилом: закладки гостя дістаються акаунту, який увійшов
першим після гостя.

1. Локальний список порожній — нічого.
2. `events.cards(ids)` — відкинути зниклі й минулі. Один рядок з неіснуючим `event_id` валить увесь масив
   (`saved_events.event_id references events`).
3. Один `POST /rest/v1/saved_events` масивом `{user_id, event_id}` з `on_conflict=user_id,event_id` і
   `resolution=ignore-duplicates`. Новий метод `SavedEvents.saveAll(ids)`, поруч із наявним `save(id)`.
4. Успіх — `GuestSavedStore.write(emptyList())`. Далі `saved.savedIds()` у тому ж `load()` повертає вже об'єднаний
   список.
5. Збій — локальний список лишається, у стані `savedIds` = серверні ∪ локальні: закладки не блимають. Повтор — на
   наступному `load()`.

Вихід з акаунта: гість починає з порожнього списку. Закладки акаунта на телефоні не лишаються.

### Платформи

| | iOS | Android |
|---|---|---|
| Кнопка «Зберегти» | `EventActionsModel.toggleSaved` — без `guard signedIn`; три `auth = .save` в `EventDetailView+Sections.swift` зникають | `DetailViewModel`: `ToggleSaved` і «Купили?» без `authenticated(AuthReason.SAVE)`; `AuthReason.SAVE` видалити |
| Питання про сповіщення | `.onChange(of: root.savesMade)` → `ReminderPrompt.offer` (питає з `.notDetermined` і `.provisional`, поважає вимкнені нагадування) | За зразком `FollowPrompt` у `MainActivity`: `savesMade > 0`, прапорець `SAVE_ASKED`, дозволу ще нема |
| «Мої події» гостя | Розріз «Збережені» і рядок про вхід над ним; заглушка `guest_empty` — лише коли закладок нема | Те саме |

Стрічка головної й мапа вже кличуть `app.toggleSaved` напряму, тож працюватимуть самі, щойно спільний код перестане
віддавати `SessionRequired`.

### Тексти

- Рядок над закладками гостя: «Збережене живе на цьому телефоні. Увійдіть, щоб не загубити».
- Порожні «Мої події» гостя: заголовок «Тут буде збережене», текст «Збережіть подію — і ввечері напередодні ми про неї нагадаємо» (точна година не потрібна, а «о 18:00» читали як час самої події),
  кнопка «Увійти» лишається (приєднання й створення досі за входом).
- `guest_description`: прибрати «зберігати цікаве» — «Увійдіть, щоб приєднуватись, стежити й створювати власні
  зустрічі».
- Нагадування — без змін (`reminder_saved_body`).

### Приватність

Нічого не виходить з телефона, доки людина не ввійде, а після входу закладки — ті самі `saved_events`, що вже описані
в політиці. App Privacy / Data safety не змінюються.

## Як міряти

| Подія | Зміна | Рішення, яке вона змінює |
|---|---|---|
| `save` (нова) | `guest`: `true` / `false`. Пишеться при збереженні, не при знятті | Чи гості взагалі зберігають. Замінює `auth_wall` з `save`, що зникне, — дані для варіанта Б ([guest-channel.md](guest-channel.md)) лишаються |
| `push_open` з `reason = saved` | новий параметр `guest` | Чи нагадування повертає саме гостя |

Правило: до ~50 гостей із `save` цифри — шум ([analytics.md](analytics.md)). Далі читати:

1. Частка нових пристроїв із `save` (`guest = true`) у першу добу. Нижче 10% — гачок не той: людина не знаходить, що
   зберегти, і це проблема першої сесії, а не входу.
2. `push_open` (`saved`, `guest = true`) до кількості гостей із закладкою на майбутню подію. Якщо нагадування не
   відкривають — дивитись текст і час, а не механіку.

## Тести

- `ReminderRulesTest`: гість із закладкою отримує нагадування напередодні; гість без закладок — нічого; «за годину»
  гостю не планується.
- `MyEventsRulesTest`: гість з імпортованою закладкою — лише «Збережені», «Організую» порожнє.
- Спільний тест бібліотеки: закладка гостя → вхід → один `saveAll`, локальний список порожній; збій `saveAll` →
  локальний лишається, `savedIds` = об'єднання; вихід → порожній список гостя; злита подія → живий id.
- Руками на симуляторі iOS і емуляторі Android 13+: гість зберігає → системне питання → у списку запланованих є
  нагадування напередодні → вхід → закладка в «Моїх подіях» акаунта, `device:saved` порожній.

## Розгортання

Лише клієнт обох платформ, без сервера. Старі збірки поводяться як зараз. Їде з першою збіркою після злиття,
разом із кроками 1–6 брифу. Оцінка — S–M: найбільше роботи в «Моїх подіях» гостя на двох платформах.

## Відкриті питання

1. ~~**Питати системним вікном одразу після першої закладки?**~~ **Вирішено 20.10: питати.** Ціна відома: на iOS
   відмова у вікні знімає й тихий дозвіл, і людина втрачає навіть дайджест. Але нагадування про конкретну подію з
   тихим дозволом без банера майже марне, а кращої причини для питання, ніж «нагадати про те, що ви щойно зберегли»,
   в застосунку нема. Відповідь на вікно не рахується, як і після «Стежити» чи «Йду»: подію для неї додавати, лише
   коли з'явиться рішення, яке від цього числа зміниться.
2. **«Мої події» гостя: розріз «Збережені» чи весь екран?** Пропозиція — лише «Збережені» з рядком про вхід:
   «Йду» й «Організую» без акаунта порожні за визначенням.
