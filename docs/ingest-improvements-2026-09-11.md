# Оновлення імпорту подій — 2026-09-11

Виконано за рев’ю `ingest-review-2026-09-11.md`. Зміни стосуються локальних скриптів завантаження,
нормалізації, злиття й підготовки SQL. Production-база не змінювалася.

## Що змінено сьогодні

1. **Повернено Python-скрипти tools у Git.** У `.gitignore` додано винятки для `tools/*.py`
   і вкладених скриптів. Кеші OSM/Photon та байткод лишаються виключеними.
2. **Прибрано небезпечне автоматичне зняття подій за відсутністю у списку.** CLI більше не
   генерує масовий `retire_sql`: одна сторінка не доводить, що подію скасовано.
3. **Скасування й відкладення.** EventCancelled/EventPostponed виключаються з публікації,
   а `--report` зберігає notices. SQL оновлює конкретне джерело, URL і час сеансу.
4. **Окремі сеанси.** `source_uid` складається з URL та UTC-часу початку. Різні дати не губляться
   через однаковий URL. Повтор однієї події на кількох сторінках згортається до одного запису.
5. **Сумісність із попередніми імпортами.** Перед INSERT SQL переводить старий URL-ключ на ключ
   сеансу, коли час збігається. ID у базі не змінюється, збережені користувачами посилання лишаються.
   `previousStartDate` дозволяє так само обробити явне перенесення.
6. **Дедуплікація.** Кандидати порівнюються лише з чинними переможцями у стабільному порядку.
   Одне спільне слово в двох багатослівних назвах уже не є достатнім збігом. Усунено повторні
   source_uid перед багаторядковим INSERT. JSON містить походження та `duplicate_of`.
7. **Прибирання старих дублів.** SQL знімає відому копію тільки якщо заміна вже live у поточному
   run_id. Якщо копію перенесено, перевіряється також явно оголошена попередня дата.
8. **Географія.** Подія іншого міста не використовує індекс міста обходу. Усі прийняті координати
   перевіряються за bbox, включно з aliases. Додано координати GeoCoordinates із джерела, коли
   немає збігу з індексом. Їх не видаємо за OSM у кеші venues. Онлайн-події йдуть на review.
9. **Нормалізація.** Заголовок вкладається у 120 символів разом із багатокрапкою; NaN, Infinity,
   від’ємні та явно не-UAH ціни відкидаються. Невалідний зсув часового поясу не валить імпорт.
   Події, які вже почались, зберігаються в дампі, якщо джерело явно оголосило майбутній endDate.
10. **HTTP та діагностика.** До трьох спроб для транспортних помилок, 429 і тимчасових 5xx;
    враховується Retry-After. Якщо він довший за 60 секунд, помилка повертається без раннього
    повтору. Заборона robots і порожній результат парсера стають помилками джерела.
11. **SQL-артефакти.** Автоматична реєстрація відсутніх джерел без перезапису наявних налаштувань;
    адресні ключі venues включають місто; byte limit ділить INSERT між записами; manifest містить
    порядок файлів, розміри та SHA-256. Ліміти перевіряються до запису файлів.
12. **Probe.** `probe_event_sources.py` використовує ті самі fetch/extract/harvest, що й імпорт.
    Додано `--source`, `--city`, `--sample`, `--json`. Свіжість більше не виводиться з року lastmod
    sitemap; оцінюються фактичні дати подій. Вкладений JSON-LD більше не дає хибного нуля.

## Нове джерело

**TicketsBox** увімкнено для Києва, Львова та Одеси. Живі списки дали відповідно 69, 24 та 2
посилання на картки свого міста. Харків і Дніпро відповідають HTTP 200, але карток у пробі не
знайдено — ці міста для нового джерела не додано.

На відміну від списку, детальні картки TicketsBox містять Event JSON-LD: startDate/endDate,
eventStatus, адресу й іноді geo. Перевірено, зокрема, картку Kyiv Food and Wine Festival:
10.10.2026 11:00–11.10.2026 21:00, ВДНГ, пр-т Академіка Глушкова, 1; дата/час збігаються з
видимою датою й data-event-start. Адаптер читає лише HTTPS `/event/`-посилання на тому самому
міському домені, до 100 карток. Фестивальні абонементи з інших URL навмисно не перетворюються
на вигадані сеанси.

Живі сторінки: [Київ](https://kyiv.ticketsbox.com/), [Львів](https://lviv.ticketsbox.com/),
[Одеса](https://odesa.ticketsbox.com/), [приклад картки](https://kyiv.ticketsbox.com/event/kyiv-food-and-wine-festival.html).

DOU перевірено, але адаптер не ввімкнено: потрібне окреме розкриття адрес і фільтрація онлайн-курсів.
Моє місто лишається вимкненим: проба дала 19 JSON-LD подій, серед них застарілі startDate та
відсутні endDate при видимих тривалих розкладах. Автоматично вважати їх живими не можна.

## Перевірки

- `python3 -m tools.ingest.test_ingest` — усі попередні перевірки проходять.
- `python3 -m unittest tools.ingest.test_regressions -v` — 28 регресійних тестів.
- Ізольований PostgreSQL через PGlite 0.5.8: виконано реальний SQL, перевірено повторний імпорт,
  збереження старого ID, два сеанси одного URL, скасування одного з них, перенесення та зняття
  старої дати дублікату. Виконано двічі SQL живих прогонів TicketsBox і трьох попередніх джерел.
- Незалежне рев’ю виявило два додаткові дефекти (повтор сеансу між сторінками та попередня дата
  дублікату); обидва виправлено й покрито тестами. Повторна перевірка також закріпила збереження
  previousStartDate при об’єднанні списку з детальною карткою.
- Новий probe перевірено на двох львівських картках: обидві містять актуальні дати й endDate;
  обмеження вибірки на 2 з 24 карток явно відображено в JSON-звіті.

PGlite потрібен лише для інтеграційного тесту; конвеєр досі використовує стандартну бібліотеку
Python. Тестова схема відтворює колонки й основні обмеження імпорту, але не весь застосунок,
RLS/auth чи PostGIS. Запуск із встановленим PGlite:

```bash
node tools/ingest/test_sql.mjs /absolute/path/to/@electric-sql/pglite/dist/index.js
```

## Межі поточної реалізації

- Списки не вважаються повним реєстром. Без явного скасування зниклі події автоматично не
  відкликаються; TTL/повторні перевірки та окремий список переносів Karabas ще не реалізовані.
- Скасування без дати безпечно оновлює лише старий URL-ключ. Для нових сеансів спільного URL
  воно зберігається у звіті й потребує уточнення, щоб не скасувати всі дати помилково.
- Перенесення без previousStartDate не можна надійно відрізнити від додаткового сеансу.
- Злиття обирає канонічну копію; повна таблиця походжень і сталий ID між різними продавцями
  ще не додані. Тимчасова недоступність продавця може залишити стару копію до наступного
  успішного спільного обходу. SQL-знімки слід застосовувати в хронологічному порядку.
- Тривалі події тепер присутні в дампі, але поточні фільтри клієнта/БД можуть показувати лише ті,
  що ще не почались. Поведінку застосунку цими змінами не змінено.
- Геокеші не отримали TTL, географічні псевдоніми міських назв ще не уніфіковані.

## Інтеграція першої трійки джерел

Після дослідження реалізовано три групи:

1. **DOU + йой!.** DOU увімкнено для Києва, Дніпра, Харкова, Львова й Одеси; йой! — для
   перевіреного Львова. Адаптер обходить картки, фільтрує фактичне місто й online, читає
   VEVENT із iCal, розгортає folded lines і не плутає DTSTART часового поясу з подією.
   Відхиляються all-day, recurring, сторонній TZID і 00:00 як непідтверджений час.
   Коли DOU прямо веде на йой!, точні endDate, offers та image доповнюють DOU-картку.
2. **Локальна культура і спорт.** lviv.travel увімкнено для Львова: точні програми
   розбиваються на окремі сеанси за h4 + повною датою/часом + адресою. Жива проба
   програми Днів європейської спадщини дала 113 розібраних сеансів, із них 27
   майбутніх/триваючих на час проби; без геоіндексу вони чесно лишилися review.
   Консервативні адаптери Артсвіт, YermilovCentre і Run Ukraine додано, але джерела
   вимкнено до появи точних підтверджених сеансів/доступного robots. Відносні дати,
   години роботи та періоди програм не стають вигаданими подіями.
3. **Статуси Karabas.** За замовчуванням перед міськими обходами читаються перші три
   сторінки офіційної таблиці скасувань/переносів. Приймається лише точний URL, місто,
   статус і дата; desktop/mobile конфлікт карантинить URL. Для переносу додатково
   завантажується картка нової дати. SQL зберігає event ID, вставляє актуальний сеанс
   і відкликає лише стару дату. Виміряний київський dry-run знайшов 7 точних notices
   у перших трьох сторінках і підготував 126 live-подій; production SQL не застосовувався.

Додано 36 нових тестів адаптерів та інтеграції; разом виконано 64 тести. Перевірено
компіляцію tools і `git diff --check`. Географічний фільтр цих імпортерів стосується лише
п’яти міст; користувацькі події в інших країнах та містах не змінюються.
