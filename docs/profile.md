# Профіль

Стан на 2026-09-24. До цього профіль був лише налаштуваннями: після входу не видно ні імені, ні пошти, імʼя не змінити, аватар у чаті й ростері — перша літера. Організатор бачив запит як «імʼя + дві кнопки» і не мав на що спертися, щоб вирішити.

## Вимоги

**Свій профіль (вкладка «Профіль», після входу)**

- В1. Шапка: аватар (фото або перша літера), імʼя, пошта, «з нами з <місяць рік>», лічильники «організував / відвідав».
- В2. «Редагувати профіль» — шторка: імʼя (1–80, обовʼязкове), «Про себе» (до 300, необовʼязкове), фото.
- В3. Фото: системний Photo Picker (без дозволу на галерею), перекодування в JPEG без EXIF, довша сторона 512 px; «Видалити фото». Кадрування не робимо: аватар кругло обрізається при показі.
- В4. Імʼя й «Про себе» проходять серверний стоп-словник (той самий, що для подій і чату); відмова — зрозумілий текст, поле лишається заповненим.

**Картка людини (чужий профіль)**

- В5. Відкривається тапом по: рядку запиту на участь, учаснику в списку «Йдуть», автору в чаті, організатору на сторінці події.
- В6. Показує фото, імʼя, «Про себе», «з нами з …», лічильники. Пошта — ніколи.
- В7. Дії: для запиту до моєї події — «Прийняти» / «Відхилити» прямо в картці; для будь-кого, крім себе, — «Поскаржитись» і «Заблокувати».
- В8. Хто кого бачить — та сама межа, що вже діє для `profiles` (`private.can_see_profile`): організатор ↔ учасники й ті, хто проситься; підтверджені учасники одне одного; автори чату. Плюс організатор опублікованої події видний будь-кому з акаунтом — його імʼя й так публічне на картці події. Блокування в будь-який бік і обмежений модерацією акаунт ховають картку. Гість карток не бачить.

**Аватар всюди**

- В9. Чат, ростер, запити, заблоковані — вже читають `profiles.avatar_url`; після В3 там зʼявляється фото без змін у цих запитах.

**Модерація й дані**

- В10. Скарга на людину (вже є) покриває фото й «Про себе»; модератор має `moderate_profile` — прибрати фото, «Про себе» або скинути імʼя.
- В11. Видалення акаунта прибирає фото (Edge Function уже видаляє все під `<uid>/`), експорт даних включає `bio` (бере весь рядок `profiles`).

Поза обсягом (додати, коли попросять): кадрування фото, соцмережі в профілі, публічна сторінка профілю за посиланням, рейтинг організатора в картці (оцінки зараз приватні для організатора — це окреме рішення про приватність).

## Архітектура

```
SwiftUI / Compose                shared (KMP)                          Supabase
ProfileView ─ EditProfileSheet ─▶ PoruchApp.saveProfile/…Avatar ─▶ ProfileRepository ─▶ PATCH profiles (тригер: стоп-словник, шлях фото)
PersonSheet (Detail, Chat)    ─▶ PoruchApp.openPerson/closePerson                   ─▶ POST rpc/profile_card
                                  AppState.library.profile (свій)                   ─▶ Storage event-images/<uid>/avatar/<uuid>.jpg
                                  AppState.person (відкрита картка)
```

**Бекенд** — міграція `20260924100000_profiles.sql`:

- `profiles.bio` (≤ 300) і `profiles.created_at` (заповнено з `auth.users`); грант `update(bio)`.
- Тригер `profiles_validate` перевіряє й `bio`; `avatar_url` — лише `…/event-images/<свій uid>/avatar/<файл>`.
- `private.owns_image_path` пускає запис у `<uid>/avatar/<файл>` (раніше лише в теку власної події).
- `public.profile_card(uuid)` (invoker) → `private.profile_card` (definer): рядок картки з лічильниками, пошта лише для себе з JWT. Definer потрібен лічильникам — чужі членства RLS не віддає; видимість перевіряється явно.
- `public.moderate_profile(uuid, text)` — для модераторів.
- Тест `supabase/tests/profiles.sql`.

**Спільний код**

- `core/domain`: `Profile`, `ProfileRules` (межі, нормалізація), інтерфейс `ProfileRepository`.
- `core/data`: `SupabaseProfileRepository` — `profile_card`, PATCH `profiles`, завантаження/видалення фото через наявний `ImageStorage`.
- `shared`: `ProfileUseCases` (зберегти, фото, прибрати фото; старий файл видаляється після успішної заміни), `LibraryState.profile` вантажиться разом із «моїми» і зникає з акаунтом, `AppState.person` — відкрита картка; запізніла відповідь для іншої людини відкидається.

**Платформи** — однаковий набір на обох:

- Шапка профілю + `EditProfileSheet`; вибір фото — той самий пайплайн, що для фото події (Android `PickVisualMedia` + перекодування, iOS `PhotosPicker` + JPEG), з меншою стороною.
- `Avatar` — один компонент (фото або літера), ним же малює `AvatarStack`.
- `PersonSheet` — картка людини; на сторінці події — список «Йдуть» з рядками, рядок організатора, рядки запитів відкривають картку; у чаті — тап по аватару.
